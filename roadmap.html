Why this order works

Math gates programming, not the other way around. Precalculus (Collingwood) runs the whole first year in parallel with C, because C itself needs almost no math — but Big-O analysis needs logarithms (Collingwood Ch.19–21) before Skiena Ch.2 can be finished, and derivatives of trig/exponential/log functions (Corral Calculus Ch.2) need those same precalculus chapters first. That's why Skiena Ch.2 is split into (2.1–2.5), usable immediately with just growth-rate intuition, and (2.6–2.11), which waits for logarithms.

Proof technique arrives before anything that needs proof. Lewis & Zax Ch.1–4 (pigeonhole, proof techniques, induction, strong induction) come before Skiena Ch.1 (correctness arguments), before Hefferon (which is proof-heavy throughout), and before any serious algorithms work.

C and CSAPP reinforce each other by design. CSAPP Ch.2 (bits, integer/float representation) is interleaved with Beej's type chapters (14–16) because they're the same material from two angles — one is "how C treats numbers," the other is "how numbers actually look in memory." CSAPP Ch.3 (machine-level programs) doesn't start until Beej's core (Ch.1–19: functions, pointers, arrays, structs, scope) is solid, because reading compiler-generated assembly requires fluent C first.

Linear algebra and calculus are deliberately kept close together (Hefferon interleaved with Corral Calculus) because vector geometry, matrix operations, and derivatives reinforce each other, and because probability's harder material — multivariate normal (Blitzstein 7.5), Markov chains (Blitzstein Ch.11) — needs matrices and eigenvalues (Hefferon Ch.3–5) already in hand.

Probability follows its own calculus prerequisites internally. Blitzstein Ch.1–4 (counting, conditional probability, discrete random variables, expectation) need only precalculus and are placed early. Continuous random variables (Ch.5) wait for single-variable integral calculus (Corral Calculus Ch.5–6). Joint distributions and transformations (Ch.7–8) wait specifically for multivariable calculus's multiple integrals (Corral Multivariable Ch.3), not just Ch.1–2, since 2D LOTUS and change-of-variables genuinely need double integrals.

OS and CSAPP chapters are paired by subsystem, not read as two separate books. Memory virtualization (OSTEP Ch.12–24) sits next to CSAPP's Virtual Memory chapter (Ch.9); concurrency (OSTEP Ch.25–34) sits next to CSAPP's Concurrent Programming chapter (Ch.12), with Beej's Multithreading and Atomics chapters folded into the same stretch; persistence (OSTEP Ch.35–45) sits next to CSAPP's System-Level I/O (Ch.10); distribution (OSTEP Ch.46–50) sits next to CSAPP's Network Programming (Ch.11). Each pairing gives you the OS-internals view and the programmer-facing view of the same mechanism back to back.

Discrete math's automata chapters (Lewis & Zax Ch.19–20) are deliberately delayed until just before the compiler unit, since finite automata and regular languages map directly onto lexer design, while chapters that support algorithms (Order Notation, Ch.21) are placed right where Skiena's own formal treatment would otherwise be under-supported.

Randomized algorithms (Skiena Ch.6) wait for a probability review (Blitzstein Ch.1–2) even though Skiena's own Ch.6.1 is titled "Probability Review" — the supplied TOC assumes some background, and Blitzstein's early chapters supply real grounding rather than a five-page refresher.

Skiena's Part II (Ch.14–22) is treated as a catalog, not a syllabus — the book's own section is explicitly organized as "A Catalog of Algorithmic Problems" for lookup, so it is deliberately excluded from the sequential spine and instead flagged for on-demand consultation while building the projects.

Major projects

  • Small C projects (dynamic array/linked list library; sorting-algorithm library + hash table; in-memory key/value cache): placed right after the C and data-structures material each one depends on, so each project is a direct rehearsal of what was just learned, not a leap ahead.
  • Data-structures projects: same placement principle — Skiena Ch.3–4 (data structures, sorting) is immediately followed by a C project applying it.
  • Systems projects: a malloc/free allocator follows CSAPP's Virtual Memory chapter and OSTEP's memory-API material; a multithreaded TCP server follows the concurrency cluster (OSTEP Ch.25–34, CSAPP Ch.12, Beej's threading/atomics chapters) and CSAPP's Network Programming chapter; a toy bytecode VM or regex engine follows the automata chapters and closes out core C, acting as a bridge into the compiler project.
  • Compiler: placed only after (a) C is fully solid, (b) automata/regular-language theory (Lewis & Zax Ch.19–20) is done, (c) enough algorithms (divide-and-conquer, dynamic programming) exist to justify real optimization passes, and (d) CSAPP's machine-level, architecture, and linking chapters give a real target for code generation. This is deliberately late — building a compiler at the start, before any of this, would mean either faking the hard parts or learning everything the hard way mid-project.
  • Distributed key-value store: placed last, after concurrency, file systems (for persistence/write-ahead logging), networking, and OSTEP's introductory distribution unit — but genuinely depends on external material for consensus and replication (see Optional additions), since none of the ten supplied books teach that.

Sophomore-year stopping point

Stop after Lewis & Zax Ch.18 (Coloring) — the point in the sequence right after "C Project #2 — a small sorting-algorithm library and a hash table."

By that point you will have:

  • Finished precalculus (Collingwood, all 23 chapters).
  • Finished C fundamentals through the preprocessor (Beej Ch.1–19), plus two small C projects.
  • Worked through discrete math from the pigeonhole principle through graph coloring (Lewis & Zax Ch.1–18) — pigeonhole, proof technique, induction, sets, relations, propositional/quantificational logic, digraphs, undirected graphs, connectivity, coloring.
  • Started algorithmic thinking: Skiena Ch.1–4 (algorithm design, analysis/Big-O, data structures, sorting).
  • Read CSAPP's opening survey chapter (Ch.1) as orientation, plus the data-representation chapter (Ch.2) alongside C's type system.

This is intentionally not a light year — rebuilding precalculus properly while learning C and starting discrete math and algorithms is a full year's worth of consistent, unhurried work. Calculus, linear algebra, probability, computer architecture beyond the survey level, operating systems, and both major projects are explicitly not part of sophomore year. Trying to compress them in would trade mastery for coverage, which section 5 of the brief for this roadmap explicitly rules out.

Later roadmap

Junior year (roughly): Corral Calculus (all 9 chapters) interleaved with Hefferon Linear Algebra (Ch.1–5) and the remaining C chapters (20–34); Lewis & Zax Ch.19–21 (automata, regular languages, order notation); Skiena Ch.5–6 (divide and conquer, hashing/randomized algorithms); CSAPP Ch.3–6 (machine-level programs, architecture, program optimization, memory hierarchy); Blitzstein Ch.1–6 (counting through moments); OSTEP's virtualization unit (Ch.1–24) paired with CSAPP Ch.9 (Virtual Memory); Corral Multivariable Calculus Ch.1–3; Systems Project #1 (malloc/free allocator) and Project #4 (cache-locality rewrite).

Senior year (roughly): CSAPP Ch.7–8, 10–12 (linking, exceptional control flow, system I/O, networking, concurrency) paired with the rest of OSTEP (concurrency, persistence, distribution); Skiena Ch.9–13 (combinatorial search through algorithm-design methodology); Blitzstein Ch.7–13 (joint distributions through Poisson processes); Corral Multivariable Ch.4 (optional enrichment); the remaining Beej reference chapters (31–41); Systems Project #2 (multithreaded server) and Project #3 (VM/regex engine/storage engine) — this is where the foundation ends.

What comes after this roadmap

Deliberately not sequenced here, since it depends on which of your two interests pulls harder once you're standing on this foundation — and both forks share the same C → systems-language transition, so you don't have to choose early:

  • Either direction starts with a systems language beyond C. Compilers/DB work and low-latency/quant work both point at modern C++; low-latency work in particular is almost always C++ specifically (Rust is common in newer systems/DB work but rare in HFT/quant shops, where the tooling, profilers, and hiring bar assume C++). A Tour of C++ (Stroustrup) then Effective Modern C++ (Meyers) is a reasonable pair either way.
  • Compilers/DB fork: a real compiler-construction text (Crafting Interpreters for an approachable pass, Engineering a Compiler by Cooper & Torczon for something more rigorous) feeding into a compiler project; a real distributed-systems/database text (Designing Data-Intensive Applications by Kleppmann, the Raft paper, or CMU 15-445/645's public materials) feeding into a distributed KV store or small database engine.
  • Low-latency/quant fork: less about a single canonical text and more about depth in what CSAPP Ch.5–6 opened up — lock-free programming, cache-conscious data structures, NUMA effects, kernel-bypass networking — plus, notably, a much heavier probability/statistics bar than DB work needs, which is exactly why Blitzstein isn't skippable in the foundation above.
  • Watch which one actually grabs you while working through Systems Project #3 above — whether you enjoy "build something correct that scales" more, or "build something correct that's fast enough to matter in microseconds" more, is a better signal than deciding it in the abstract now.

Optional additions

Now that the roadmap is scoped to foundation only, there isn't a genuine gap the way there was before — the ten supplied books cover math, discrete math, DSA, C, and computer systems (architecture, performance, memory, OS, networking, concurrency) adequately for that scope on their own. Nothing needs to be added to complete the foundation as defined.

What used to be listed here — a modern C++ book, a compiler-construction book, distributed-systems material covering consensus and replication — are real gaps, but they're gaps in the next stage, not this one. They're addressed in "What comes after this roadmap" above instead, since which of them you need first depends on which fork (compilers/DBs vs. low-latency/quant) you end up pursuing.

Worth knowing about if you want more depth than the foundation requires, but not necessary for either fork above:

  • A dedicated computer-architecture book (e.g., Patterson & Hennessy) beyond CSAPP Ch.3–6 and Ch.9 — CSAPP's treatment (including the Y86-64 ISA, pipelining, and the memory hierarchy) is sufficient for a strong working understanding; only matters if you want microarchitecture depth beyond what either fork requires.
  • A dedicated networking book (e.g., Kurose & Ross) beyond CSAPP Ch.11 — sufficient sockets-level knowledge for either fork; only necessary for protocol-level depth.

Precision notes / flags

  • Corral — Calculus and Corral — Multivariable Calculus: the supplied TOC lists chapter numbers with bulleted topic names but no numbered subsections (e.g., "1. The Derivative" followed by unnumbered bullets). These are therefore used at whole-chapter granularity throughout; no subsection numbers have been invented.
  • Lewis & Zax — Discrete Mathematics: the supplied TOC lists only chapter numbers and titles, no subsections. Used at whole-chapter granularity throughout.
  • Hefferon — Linear Algebra: uses Roman-numeral top-level sections (I, II, III...) with decimal subsections (I.1, I.2...) rather than a chapter.section scheme. That notation is preserved exactly as given (e.g., "Hefferon Ch.1 (I.1–I.3)") rather than converted to an arabic-numeral format not present in the source.
  • Beej — C, Ch.20–41: full sub-section numbers for these later chapters were not itemized in this pass (they exist in the source but were not extracted section-by-section); these chapters are therefore scheduled at whole-chapter granularity to avoid fabricating ranges.
  • Skiena — Algorithm Design Manual, Part II (Ch.14–22): the book itself frames this as "A Catalog of Algorithmic Problems," i.e., reference material, not a sequential narrative. It is intentionally excluded from the main sequential spine; Ch.15 (Data Structures catalog) is called out explicitly near the end of the roadmap as the most immediately useful reference chapter for the closing systems project, with the rest of Part II left for on-demand lookup during whatever comes after this roadmap.
  • Skiena Ch.13 ("How to Design Algorithms") is a short capstone/reflection chapter and is placed as a wrap-up to Part I rather than interleaved mid-sequence.
  • No chapters or sections from any of the ten books were invented, renamed, or skipped silently. Every chapter of every book appears somewhere above except Skiena's Part II catalog chapters, which are explicitly marked as reference material rather than omitted.
